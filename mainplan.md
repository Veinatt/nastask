1. Название проекта
TaskTracker – персональный трекер задач для фрилансера-дизайнера с гибким учётом времени, коэффициентами сложности и автоматической отчётностью.

2. Цель и основные возможности
Цель – создать приложение, которое поможет дизайнеру:

Фиксировать все выполняемые задачи (заказы) с указанием названия, объёма (количество), коэффициента сложности (для расчёта заработка).

Отслеживать время начала и завершения каждой задачи, с возможностью редактировать эти даты постфактум.

Получать напоминания о необходимости закрыть задачу (с настраиваемым интервалом), о скором старте задачи и периодические напоминания «проверьте, не появились ли новые задачи».

Настраивать рабочее время по дням недели и исключениям (выходные, изменённый график).

Формировать отчёты за месяц с группировкой по задачам и экспортом в Excel.

Работать внутри Telegram (Mini App) на любых устройствах с поддержкой светлой и тёмной темы.

4. Функциональные требования (детально)
4.1. Управление задачами
Создание задачи:

Поля:

title – текст, обязательно.

quantity – число > 0 (например, количество баннеров).

coefficient – число с плавающей точкой (по умолчанию 1.0, шаг 0.1).

reminderInterval – выпадающий список: '15m' | '30m' | '1h' | '2h' | '3h' | '4h' | 'daily'.

startTime – дата и время начала работы (по умолчанию – текущее время, но пользователь может изменить или очистить).

deadline – дата и время дедлайна (опционально, по умолчанию пусто).

При сохранении создаётся задача со статусом active.

Генерируется уникальный id (можно использовать crypto.randomUUID()).

Фиксируются createdAt и updatedAt (автоматически).

Редактирование задачи:

Можно изменять любые поля, включая startTime, deadline, а для завершённых задач – также completedAt.

При изменении startTime или reminderInterval пересчитывается расписание напоминаний (если задача ещё активна).

При изменении completedAt задача автоматически перегруппируется в отчётах по новому месяцу завершения.

Завершение задачи:

При нажатии кнопки «Завершить» задача переходит в статус completed.

Автоматически проставляется completedAt = текущее время ISO.

Пользователь может позже отредактировать completedAt (например, если забыл завершить задачу вчера).

После завершения задача больше не участвует в уведомлениях.

Удаление задачи:

Можно полностью удалить задачу (жёсткое удаление) или архивировать (мягкое) – на выбор. Рекомендуется жёсткое удаление с подтверждением.

Список задач:

Отображение активных задач (статус active) в виде карточек с краткой информацией: название, количество, коэффициент, интервал, время старта (если указано).

Кнопки: «Редактировать», «Завершить», «Удалить».

Возможность фильтрации (например, показать завершённые задачи).

4.2. Настройки
Рабочее время:

Для каждого дня недели (пн–вс): чекбокс «Включено», время начала и окончания (HH:mm).

Исключения:

Список дат (YYYY-MM-DD) с возможностью указать для каждой даты своё рабочее время или сделать выходной (флаг isOff).

Добавление/удаление исключений.

Время упреждения для старта:

Числовое поле (часы) – за сколько часов до startTime отправлять уведомление о скором старте (по умолчанию 1 час).

Напоминание «Проверьте новые задачи»:

Переключатель (вкл/выкл).

Интервал – выпадающий список: 15м, 30м, 1ч, 2ч, 3ч, 4ч, раз в сутки.

(Опционально) Время первого уведомления после начала рабочего дня – можно задать смещение (например, через 1 час), чтобы не беспокоить сразу.

4.3. Уведомления (реализация на клиенте в MVP, позже – на сервере)
Типы уведомлений:

О скором старте задачи – если у задачи указан startTime и текущее время = startTime - reminderLeadTime. Отправляется однократно.
О незакрытой задаче – если задача активна и с момента последнего уведомления прошло больше, чем reminderInterval, и текущее время попадает в рабочее (с учётом исключений). Отправляется периодически.
Периодическое напоминание «Проверьте новые задачи» – если функция включена, и наступило время следующего такого уведомления (по своему интервалу). Отправляется независимо от наличия задач.
Все уведомления отправляются только в рабочее время (с учётом исключений). Если время выпадает на нерабочее, следующее уведомление переносится на ближайшее рабочее время.

Для каждого типа уведомлений хранится время последней отправки (в памяти или в БД), чтобы избежать дублирования.

В MVP используются браузерные уведомления (Notification API). На втором этапе перейдём на отправку через Telegram-бота (push-уведомления).

4.4. Отчёты
Страница с выбором месяца (использовать компонент MonthPicker).

Таблица со всеми завершёнными задачами за выбранный месяц:

Колонки: Название, Количество, Коэффициент, Дата создания, Дата завершения, Сумма (количество × коэффициент).

Итоговая строка с общей суммой за месяц.

Кнопка «Экспорт в Excel» – генерирует файл .xlsx с теми же данными и скачивает его.

4.5. Интеграция с Telegram (Mini App)
Приложение запускается внутри Telegram (WebApp).

Используем @telegram-apps/sdk-react для:

Получения данных пользователя (userId, initData).

Автоматической синхронизации темы (светлая/тёмная) с настройками Telegram.

В будущем (для серверных уведомлений) userId и initData будут использоваться для аутентификации.

4.6. Дизайн и темизация
Используем shadcn/ui как основу компонентов (адаптивный, доступный, кастомизируемый через CSS-переменные).

Тёмная и светлая тема переключаются автоматически (поддержка prefers-color-scheme и синхронизация с Telegram). Можно добавить ручной переключатель (но по условию – автоматическая).

Верстка адаптивная – приоритет мобильным устройствам.

5. Модели данных (TypeScript)
5.1. Интерфейс задачи
ts
interface Task {
  id: string;                      // уникальный, генерируется на клиенте
  title: string;
  quantity: number;
  coefficient: number;             // например, 1.0, 1.5
  reminderInterval: '15m' | '30m' | '1h' | '2h' | '3h' | '4h' | 'daily';
  startTime: string | null;        // ISO строка с часовым поясом, может быть null
  deadline: string | null;         // ISO строка, опционально
  status: 'active' | 'completed' | 'cancelled';
  createdAt: string;               // ISO, фиксируется при создании
  completedAt: string | null;      // ISO, заполняется при завершении, редактируема
  updatedAt: string;               // ISO, обновляется при каждом изменении
  // Поля для управления уведомлениями (можно хранить здесь или отдельно)
  lastReminderSent: string | null; // время последнего отправленного напоминания о закрытии
  startNotified: boolean;          // было ли отправлено уведомление о скором старте
}
5.2. Интерфейс настроек
ts
interface Settings {
  workSchedule: {
    monday: { enabled: boolean; start: string; end: string };
    tuesday: { enabled: boolean; start: string; end: string };
    // ... аналогично для всех дней
    sunday: { enabled: boolean; start: string; end: string };
  };
  exceptions: {
    date: string;                // YYYY-MM-DD
    start?: string;              // HH:mm (опционально, если isOff = true)
    end?: string;
    isOff: boolean;              // если true – выходной
  }[];
  reminderLeadTime: number;      // часы (по умолчанию 1)
  newTaskReminder: {
    enabled: boolean;
    interval: '15m' | '30m' | '1h' | '2h' | '3h' | '4h' | 'daily';
    // опционально: firstOffsetMinutes?: number;
  };
}

8. Пошаговый план разработки (MVP на клиенте)
Шаг 0. Инициализация проекта
Создать папку frontend, инициализировать Vite с React + TypeScript.

Установить зависимости: react-router-dom, tailwindcss, shadcn/ui, dexie, react-hook-form, zod, xlsx, @telegram-apps/sdk-react.

Настроить Tailwind и shadcn/ui (следовать официальной документации).

Создать базовую структуру папок.

Шаг 1. Модели данных и работа с IndexedDB
Создать файлы src/db/types.ts и src/db/index.ts.

Инициализировать dexie, создать таблицы tasks и settings.

Реализовать методы CRUD для задач и настроек.

Шаг 2. Хуки
useTasks – инкапсулирует все операции с задачами, подписывается на изменения БД (можно использовать useLiveQuery из dexie-react-hooks).

useSettings – аналогично для настроек.

useTelegram – инициализация SDK, получение userId и темы.

useNotifications – логика проверки уведомлений (см. раздел 4.3).

Шаг 3. Компоненты UI
Сгенерировать базовые компоненты shadcn/ui через CLI (или установить вручную).

Создать:

TaskCard – отображение задачи.

TaskList – список карточек с фильтром.

TaskForm – модальное окно с полями (react-hook-form + zod).

SettingsPage – форма для рабочего времени, исключений и настроек уведомлений.

ReportsPage – таблица с задачами за месяц и кнопка экспорта.

AppLayout – обёртка с навигацией.

Шаг 4. Маршрутизация
Использовать React Router v6.

Определить маршруты: / (задачи), /reports, /settings.

Добавить нижнюю навигацию (TabBar) для мобильных устройств.

Шаг 5. Уведомления (клиентские)
В хуке useNotifications реализовать периодическую проверку (каждую минуту).

Для каждой активной задачи вычислить, нужно ли отправить уведомление (с учётом рабочего времени и интервала).

Для типа «проверьте новые задачи» – аналогично, но с отдельным интервалом и переключателем.

Использовать браузерный Notification API (запросить разрешение при первом запуске).

Шаг 6. Отчёты и экспорт
На странице отчётов использовать getTasksByMonth.

Отображать данные в таблице shadcn/ui.

Реализовать экспорт через библиотеку xlsx.

Шаг 7. Интеграция с Telegram
Обернуть приложение в TelegramProvider из SDK.

Подписаться на изменение темы и переключать класс dark.

Получить userId для будущей отправки на сервер.

Шаг 8. Тестирование и отладка
Проверить все сценарии (создание, редактирование, завершение, удаление).

Проверить уведомления (для локальной разработки нужен HTTPS или localhost).

Проверить адаптивность.

Шаг 9. Деплой (первый этап)
Собрать проект (npm run build).

Задеплоить на Vercel или Netlify как статический сайт.

Создать бота в Telegram через @BotFather, настроить Mini App (указать URL).

Протестировать работу в Telegram.
