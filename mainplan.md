1. Название проекта
NasTask – персональный трекер задач для фрилансера-дизайнера с гибким учётом времени, коэффициентами сложности и автоматической отчётностью.

2. Цель и основные возможности
Цель – создать приложение, которое поможет дизайнеру:

Фиксировать все выполняемые задачи (заказы) с указанием названия, объёма (количество), коэффициента сложности (для расчёта заработка).

Отслеживать время начала и завершения каждой задачи, с возможностью редактировать эти даты постфактум.

Получать push-уведомления в Telegram (через бота) о необходимости закрыть задачу (с настраиваемым интервалом), о скором старте задачи и периодические напоминания «проверьте, не появились ли новые задачи».

Настраивать рабочее время по дням недели и исключениям (выходные, изменённый график).

Формировать отчёты за месяц в виде таблицы и календаря с группировкой по задачам и экспортом в Excel.

Работать внутри Telegram (Mini App) на любых устройствах с поддержкой светлой и тёмной темы.

4. Функциональные требования (обновлённые)
4.1. Управление задачами
Создание задачи:

Поля:

title – текст, обязательно.

quantity – число > 0.

coefficient – число с плавающей точкой (по умолчанию 1.0, шаг 0.1).

reminderInterval – выпадающий список: '15m' | '30m' | '1h' | '2h' | '3h' | '4h' | 'daily'.

startTime – дата и время начала (по умолчанию – текущее время, но можно изменить или очистить).

deadline – дата и время дедлайна (опционально).

При сохранении создаётся задача со статусом active.

Генерируется уникальный id (crypto.randomUUID()).

Фиксируются createdAt и updatedAt.

После сохранения в IndexedDB клиент отправляет POST-запрос на бэкенд для регистрации расписания уведомлений (передаются: taskId, userId, title, startTime, interval, deadline).

Редактирование задачи:

Можно изменять любые поля, включая startTime, deadline, а для завершённых – также completedAt.

При изменении startTime или reminderInterval клиент отправляет PUT-запрос на бэкенд для обновления расписания.

При изменении completedAt задача автоматически перегруппируется в отчётах.

Завершение задачи:

При нажатии «Завершить» задача переходит в completed, проставляется completedAt = текущее время ISO.

Клиент отправляет DELETE-запрос на бэкенд, чтобы удалить расписание уведомлений для этой задачи.

Удаление задачи: жёсткое удаление с подтверждением.

Список задач: отображение активных задач карточками, кнопки «Редактировать», «Завершить», «Удалить».

4.2. Настройки
Рабочее время: для каждого дня недели – чекбокс «Вкл», время начала и окончания (HH:mm).

Исключения: список дат с возможностью указать своё рабочее время или выходной.

Время упреждения для старта: числовое поле (часы) – за сколько часов до startTime отправлять уведомление (по умолчанию 1).

Напоминание «Проверьте новые задачи»:

Переключатель (вкл/выкл).

Интервал – выпадающий список: 15м, 30м, 1ч, 2ч, 3ч, 4ч, раз в сутки.

(Опционально) Смещение первого уведомления после начала рабочего дня.

Важно: Настройки хранятся локально в IndexedDB, но при отправке данных на бэкенд клиент должен передавать текущие настройки рабочего времени вместе с задачей (или отдельным запросом), чтобы сервер мог корректно вычислять время уведомлений с учётом графика пользователя.

4.3. Уведомления (только через Telegram-бота)
Все уведомления отправляются через бота – клиент не использует браузерный Notification API.

Типы уведомлений:

О скором старте задачи – за reminderLeadTime часов до startTime. Текст:
«🔔 Задача "{{title}}" скоро начнётся (через {{reminderLeadTime}} ч). Не забудьте приступить!»
О незакрытой задаче – с заданным интервалом в рабочее время. Текст:
«⏰ Напоминание: задача "{{title}}" (количество: {{quantity}}, коэффициент: {{coefficient}}) ещё не завершена. Проверьте в приложении.»
Периодическое напоминание «Проверьте новые задачи» – если включено в настройках. Текст:
«📋 Проверьте, не появились ли новые задачи? Не забудьте внести их в трекер NasTask!»
Логика на бэкенде:

В таблице reminders хранятся: taskId, userId, title, nextNotify (timestamp), interval, startTime, deadline, reminderLeadTime, workSchedule (JSON) – или настройки передаются отдельно.

Cron-задача каждую минуту проверяет, наступило ли время для отправки.

При отправке обновляет nextNotify на основе интервала и рабочего времени.

Если задача завершена – запись удаляется.

4.4. Отчёты (с календарём)
Страница с выбором месяца.

Два режима просмотра:

Таблица – список завершённых задач с колонками: название, количество, коэффициент, дата создания, дата завершения, сумма.

Календарь – визуальное отображение дней месяца с отметками о задачах (например, точки или цветные индикаторы). При клике на день – список задач, завершённых в этот день.

Итоговая строка с общей суммой за месяц.

Кнопка «Экспорт в Excel» – скачивание .xlsx с данными таблицы.

Календарь – это клиентская фича, бэкенд не участвует. Данные берутся из IndexedDB.

4.5. Интеграция с Telegram (Mini App)
Приложение запускается внутри Telegram (WebApp).

Используем @telegram-apps/sdk-react для:

Получения userId и initData (для аутентификации на бэкенде).

Автоматической синхронизации темы (светлая/тёмная).

При отправке данных на бэкенд клиент передаёт userId (и, опционально, initData для проверки подписи).

4.6. Дизайн и темизация
shadcn/ui – адаптивный, с CSS-переменными для светлой/тёмной темы.

Тема переключается автоматически (синхронизация с Telegram), можно добавить ручной переключатель.

Приоритет мобильным устройствам.

interface Settings {

5.3. Интерфейс для отправки на бэкенд (POST /reminders)
ts
interface ReminderPayload {
  taskId: string;
  userId: number;
  title: string;
  quantity?: number;        // для информативности в уведомлениях
  coefficient?: number;     // для информативности
  startTime: string | null; // ISO
  interval: string;
  deadline?: string | null;
  reminderLeadTime: number; // из настроек
  workSchedule: Settings['workSchedule']; // чтобы сервер учитывал рабочее время
  // возможно, исключения тоже
}
5.4. Таблица бэкенда (SQLite)
sql
CREATE TABLE reminders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  taskId TEXT UNIQUE NOT NULL,
  userId INTEGER NOT NULL,
  title TEXT NOT NULL,
  nextNotify INTEGER NOT NULL,        -- Unix timestamp
  interval TEXT NOT NULL,
  startTime INTEGER,                  -- Unix timestamp
  deadline INTEGER,
  reminderLeadTime INTEGER,
  workSchedule TEXT,                  -- JSON
  createdAt INTEGER DEFAULT (strftime('%s', 'now'))
);

7. Пошаговый план разработки (обновлённый)
Этап 0: Подготовка
Создать проект Vite с React+TS.

Установить зависимости (включая @telegram-apps/sdk-react).

Настроить Tailwind и shadcn/ui.

Этап 1: Модели данных и IndexedDB (без изменений)
Создать интерфейсы Task, Settings.

Реализовать CRUD через dexie.

Этап 2: Хуки и API-клиент
useTasks – все операции с задачами + вызовы API-клиента.

useSettings – настройки.

useTelegram – получение userId, темы.

API-клиент – функции createReminder, updateReminder, deleteReminder (см. раздел 5.3).

Этап 3: Компоненты UI
TaskList, TaskCard, TaskForm (без уведомлений, только локальное сохранение).

SettingsPage – настройки рабочего времени, исключений, переключатели для уведомлений.

ReportsPage – таблица + календарь (использовать shadcn/ui Calendar или написать свой).

Этап 4: Интеграция с бэкендом
При создании/редактировании/завершении задачи – отправлять данные на бэкенд.

Обрабатывать ошибки (не блокировать UI).

Использовать переменную окружения VITE_API_URL.

Этап 5: Деплой фронтенда на Vercel
Собрать проект, залить на GitHub, подключить к Vercel.

Этап 6: Создание бэкенда
Node.js + Express + SQLite + Telegraf + node-cron.

Реализовать:

POST /reminders – создание/обновление расписания.

DELETE /reminders/:taskId – удаление.

Cron-задачу, отправляющую уведомления через бота.

Задеплоить на Render.

Этап 7: Связка и тестирование
Проверить, что при создании задачи бот присылает уведомление.

Проверить периодические напоминания.

Проверить работу календаря и отчётов.

Этап 8: (Опционально) Доработки
Добавить аутентификацию через initData.

Улучшить внешний вид, анимации.

8. Ожидания от Cursor
Прошу Cursor:

Генерировать код с учётом того, что уведомления только через бэкенд, на клиенте никаких Notification.

В API-клиенте использовать fetch и обрабатывать ошибки.

Для календаря использовать компонент Calendar из shadcn/ui или написать свой на основе date-fns.

При отправке данных на бэкенд передавать все необходимые поля (включая workSchedule и reminderLeadTime).

Предоставлять код с комментариями на русском или английском.

9. Итоговый продукт
После завершения всех этапов мы получим:

NasTask – полноценное Telegram Mini App.

Все данные о задачах хранятся локально (IndexedDB).

Уведомления приходят через Telegram-бота, даже если приложение закрыто.

Отчёты с таблицей и календарём, экспорт в Excel.

Полностью настраиваемые рабочие часы и интервалы напоминаний.
