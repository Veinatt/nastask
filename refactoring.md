# 🚀 NasTask — Полный промт для рефакторинга (обновлённая версия)

Этот документ — **единый источник истины** для рефакторинга проекта NasTask. Он содержит все требования, архитектурные решения, модели данных, API, интерфейсы и пошаговый план действий. Используйте его как контекст для Cursor при генерации кода.

---

## 📌 Текущее состояние проекта

- **Frontend**: React + Vite + TypeScript, shadcn/ui, Tailwind, Dexie (IndexedDB), @telegram-apps/sdk-react, xlsx.
- **Backend**: Node.js + Express + SQLite (better-sqlite3), Telegraf (только для /start), без cron.
- **Деплой**: Frontend → Vercel, Backend → Railway (с Volume для SQLite).
- **Авторизация**: Telegram initData через заголовок `Authorization: tma ...`.
- **Устаревшие сущности**: `tasks`, `reminders`, `user_settings` (старые), `cron`, напоминания.

**Что нужно сделать**: полностью переработать приложение под новый концепт **трекера времени с интервалами и работами**, удалив всё, что связано со старыми задачами и уведомлениями.

---

## 🧠 Новый концепт (кратко)

- **Интервал** — отрезок времени с названием, коэффициентом, списком выполненных работ.
- **Работа** — категория (выбирается из справочника), описание (выбирается из справочника), количество, единица измерения (выбирается из справочника). Категории и описания независимы.
- **Параллельные интервалы** — можно запускать несколько одновременно.
- **Пауза/возобновление** — для каждого интервала.
- **Завершение** — интервал завершается, работы сохраняются.
- **Два типа отчётов**:
  - Для налоговой: группировка по категориям и/или описаниям с суммированием количества.
  - Для ЗП: по интервалам (время, коэффициент, сумма).
- **Статистика** — визуальные карточки (сегодня, месяц, топ категорий/описаний).
- **Настройки** — ставка, налог, управление справочниками (категории, описания, единицы).
- **Синхронизация**: локальный кеш (IndexedDB) + сервер (SQLite), офлайн-режим с очередью операций.

## 🗄️ Новые модели данных

### SQLite (Backend)

```sql
-- Интервалы
CREATE TABLE time_entries (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  userId INTEGER NOT NULL,
  title TEXT NOT NULL,
  coefficient REAL DEFAULT 1.0,
  start TIMESTAMP NOT NULL,
  end TIMESTAMP DEFAULT NULL,          -- NULL = активен
  total_seconds INTEGER DEFAULT 0,      -- общее время работы (без пауз)
  pause_total_seconds INTEGER DEFAULT 0,-- суммарное время пауз
  date DATE NOT NULL,                   -- дата интервала (для группировки)
  is_active BOOLEAN DEFAULT 1,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Категории работ
CREATE TABLE categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  userId INTEGER NOT NULL,
  name TEXT NOT NULL,
  UNIQUE(userId, name)
);

-- Описания работ (независимые от категорий)
CREATE TABLE work_descriptions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  userId INTEGER NOT NULL,
  name TEXT NOT NULL,
  UNIQUE(userId, name)
);

-- Единицы измерения
CREATE TABLE units (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  userId INTEGER NOT NULL,
  name TEXT NOT NULL,
  UNIQUE(userId, name)
);

-- Работы внутри интервала
CREATE TABLE work_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timeEntryId INTEGER NOT NULL,
  categoryId INTEGER NOT NULL,
  descriptionId INTEGER NOT NULL,
  quantity REAL NOT NULL,
  unitId INTEGER NOT NULL,
  FOREIGN KEY (timeEntryId) REFERENCES time_entries(id) ON DELETE CASCADE,
  FOREIGN KEY (categoryId) REFERENCES categories(id),
  FOREIGN KEY (descriptionId) REFERENCES work_descriptions(id),
  FOREIGN KEY (unitId) REFERENCES units(id)
);

-- Настройки пользователя
CREATE TABLE user_settings (
  userId INTEGER PRIMARY KEY,
  hourlyRate REAL DEFAULT 0,
  taxRate REAL DEFAULT 0,
  currency TEXT DEFAULT 'BYN',
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### IndexedDB (Frontend, Dexie)

Те же таблицы + таблица `pending_ops`:

```ts
pending_ops: {
  id: string,
  operation: 'create' | 'update' | 'delete',
  entity: 'timeEntry' | 'workItem' | 'category' | 'description' | 'unit' | 'setting',
  data: any,
  timestamp: number,
  retries: number
}
```

## 🔌 Новые API-эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/api/intervals/start` | Создать активный интервал (тело: `{ title, userId }`). Возвращает `{ id, start }`. |
| `PUT` | `/api/intervals/:id/pause` | Поставить на паузу. Тело: `{ pauseStart }` (серверное время). |
| `PUT` | `/api/intervals/:id/resume` | Возобновить. Тело: `{ resumeStart }`. |
| `PUT` | `/api/intervals/:id/complete` | Завершить. Тело: `{ coefficient, workItems: [{ categoryId, descriptionId, quantity, unitId }] }`. |
| `GET` | `/api/intervals/active` | Получить все активные интервалы пользователя. |
| `GET` | `/api/intervals/completed?date=YYYY-MM-DD` | Завершённые за день. |
| `GET` | `/api/intervals/report/tax?year=YYYY&month=MM` | Отчёт для налоговой (группировка по категориям и описаниям). |
| `GET` | `/api/intervals/report/salary?year=YYYY&month=MM` | Отчёт для ЗП (по интервалам). |
| `PUT` | `/api/intervals/:id` | Обновить интервал (название, время, коэффициент, работы). |
| `DELETE` | `/api/intervals/:id` | Удалить интервал (каскадно работы). |
| `GET` | `/api/categories` | Список категорий пользователя. |
| `POST` | `/api/categories` | Создать новую категорию. |
| `DELETE` | `/api/categories/:id` | Удалить категорию (если есть работы — запретить или обнулить). |
| `GET` | `/api/descriptions` | Список описаний пользователя. |
| `POST` | `/api/descriptions` | Создать новое описание. |
| `DELETE` | `/api/descriptions/:id` | Удалить описание. |
| `GET` | `/api/units` | Список единиц измерения. |
| `POST` | `/api/units` | Создать новую единицу. |
| `DELETE` | `/api/units/:id` | Удалить единицу. |
| `GET` | `/api/settings` | Получить настройки пользователя. |
| `PUT` | `/api/settings` | Обновить настройки. |

## 🖥️ Фронтенд: страницы и компоненты

**Навигация**: 4 вкладки внизу:
- **Главная** (активные интервалы)
- **Статистика**
- **Отчёты**
- **Настройки**

### 1. Главная страница

- Список активных интервалов: каждый с названием, текущим временем, кнопками ⏸️ ▶️ ⏹️.
- Кнопка «Начать работу» → модалка с полем `title`.
- Кнопка «Добавить вручную» → модалка для создания интервала постфактум (с выбором даты/времени).
- Пустое состояние при отсутствии активных интервалов.

### 2. Статистика

- Карточка «Сегодня»: часы, количество интервалов, средний коэффициент, топ категорий и описаний (по количеству работ).
- Карточка «Этот месяц»: общие часы, динамика по дням (график или таблица), топ категорий и описаний.
- Фильтры: переключение на «вчера», «неделя», произвольный период.

### 3. Отчёты

Два режима:

- **Режим «Для налоговой»**:
  - Выбор месяца.
  - Таблица с группировкой по категориям и/или описаниям (можно переключать).
  - Колонки: Категория, Описание, Количество, Единица измерения.
  - Итоговая строка.
  - Кнопка «Экспорт в Excel» (и Google Sheets, если настроено).

- **Режим «Для ЗП»**:
  - Выбор месяца.
  - Таблица: Дата, Название, Часы, Коэффициент, Сумма.
  - Итог: всего часов, общая сумма, налог, к выплате.

**Редактирование**: при клике на строку (или по кнопке) открывается модалка редактирования интервала с возможностью изменить название, время, коэффициент и список работ (добавлять/удалять/изменять). В модалке работы отображаются с полями: категория (автодополнение), описание (автодополнение), количество, единица (автодополнение).

### 4. Настройки

- Ставка за час (числовой ввод).
- Налог (процент).
- Валюта (выпадающий список).
- Управление категориями: список с возможностью добавления/удаления.
- Управление описаниями: аналогично.
- Управление единицами измерения: аналогично.

## 🧩 Хуки и утилиты

- **`useIntervals`**: CRUD-операции для интервалов (локально + сервер), синхронизация активных при старте.
- **`useWorkItems`**: управление работами внутри интервала (добавление/удаление/обновление).
- **`useActiveIntervals`**: подписка на активные интервалы с обновлением таймеров каждую секунду.
- **`useReports`**: получение отчётов (tax/salary) для выбранного месяца.
- **`useSettings`**: настройки пользователя.
- **`useAutoComplete`**: автодополнение для категорий, описаний, единиц.
- **`useSync`**: фоновая синхронизация (отправка `pending_ops`).

---

## 🕹️ Логика синхронизации

- При старте приложения: загрузить активные интервалы с сервера, объединить с локальными.
- При любом изменении: сначала локально, затем создать `pending_ops`, отправить на сервер.
- При ошибке: повторять с экспоненциальной задержкой.
- При успехе: удалить из `pending_ops`.
- При возвращении сети: отправить все накопившиеся `pending_ops`.
